# Загрузка Stage 18A в GitHub с телефона

## До загрузки

1. Скачайте резервную копию текущего репозитория через **Code → Download ZIP**.
2. Распакуйте архив Stage 18A на телефоне.
3. В GitHub удалите старые элементы, которых нет в новом Flutter-проекте:
   - папку `views`;
   - `.github/workflows/build-apk.yml`;
   - `.github/workflows/stale.yml`;
   - `package.json`, `package-lock.json`, `server.js`, `app.js` или `index.js`, если они есть в корне.

Важно: обычная загрузка новых файлов не удаляет старые файлы автоматически.

## Загрузка

1. Откройте корень репозитория `Ugur.v1` и ветку `main`.
2. Нажмите **Add file → Upload files**.
3. Загружайте содержимое распакованной папки Stage 18A, а не сам ZIP и не внешнюю папку целиком.
4. Проверьте, что в корне видны:
   - `lib`;
   - `assets`;
   - `docs`;
   - `tool`;
   - `.github`;
   - `pubspec.yaml`;
   - `DESIGN_LOCK.json`.
5. Сделайте commit в ветку `main`.

## После загрузки

1. Откройте **Actions**.
2. Дождитесь двух запусков:
   - **Build Ugur Android APK**;
   - **Deploy Ugur Web**.
3. Оба запуска должны завершиться зелёной галочкой.
4. В Android-запуске скачайте artifact `ugur-v1.6.1-build20-debug-apk`.
5. В **Settings → Pages** источником публикации должен быть **GitHub Actions**.

Если валидатор обнаружит старые Node/EJS-файлы, сборка остановится до их удаления. Это сделано специально, чтобы GitHub больше не собирал смешанный старый проект.
